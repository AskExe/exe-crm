### 4c. AUTH: API Routes and Mutations

**Surveyed controllers and key patterns:**

| Endpoint / Controller | Guard(s) | Assessment |
|---|---|---|
| `RestApiCoreController` (`/rest/*`) | `JwtAuthGuard`, `WorkspaceAuthGuard`, `CustomPermissionGuard` | ✅ protected |
| `RestApiMetadataController` (`/rest/metadata/*`) | `JwtAuthGuard`, `WorkspaceAuthGuard` | ✅ protected |
| `McpCoreController` (`/mcp`) | `McpAuthGuard`, `WorkspaceAuthGuard`, `NoPermissionGuard` | ✅ protected |
| `DataIngestionController` (`/api/ingest`) | `JwtAuthGuard`, `WorkspaceAuthGuard` | ✅ protected |
| `ApiKeyController` (`/rest/apiKeys`) | `JwtAuthGuard`, `WorkspaceAuthGuard`, `SettingsPermissionGuard` | ✅ protected |
| `FileController` (`/public-assets/*`) | `PublicEndpointGuard`, `NoPermissionGuard` | ✅ intentionally public (static assets) |
| `RouteTriggerController` (`/s/*`) | `PublicEndpointGuard`, `NoPermissionGuard` | ✅ intentional (user-defined public webhook routes) |
| `HealthController` | None (public) | ✅ intentional |
| `GoTrueAuthController` (`/api/auth/gotrue-login`, `/api/auth/admin-token`) | None | ⚠️ intentional (auth endpoints must be public), but see P1 findings below |

**Tenant isolation:** `WorkspaceAuthGuard` is applied on all data-access controllers. The REST API uses `workspaceId` from the JWT payload, not from user input. No tenant-data endpoints found without workspace check.

**GoTrueAuthController concerns:**
- `/api/auth/admin-token` — secret is SHA-256 hashed at startup, compared with `timingSafeEqual`. Correct timing-safe compare. However, the global rate limit is 300 req/min — for a hardcoded admin token, brute-force within 300 guesses per minute is a concern. No per-endpoint lockout. (**P1**)
- `/api/auth/gotrue-login` — forwards credentials to GoTrue, no local password storage. Acceptable.
- `workspace-bootstrap.service.ts:52` — fallback `admin@askexe.com` hardcoded as default admin email if `EXE_CRM_ADMIN_EMAIL` env var is not set. This leaks the bootstrap admin address if the default is used. (**P1**)

### 4d. SQL / ORM Injection

- All raw `dataSource.query(...)` calls in `gotrue-auth.controller.ts` and `workspace-bootstrap.service.ts` use parameterized queries (`$1`, `$2`, `$3`) — no string interpolation of user input.
- No template literal raw queries with `${userInput}` pattern found in server src.
- `computeWebhooks.utils.ts:44` — generates a CJS snippet with `require("crypto")` as a code string for webhook runner; the snippet does not interpolate user-controlled values.
- **Assessment: No SQL injection vulnerabilities found.**

### 4e. CORS

- `cors: false` passed to `NestFactory.create` — disables NestJS default.
- Custom `enableCors()` in `main.ts` uses `isOriginAllowed()`: checks `FRONTEND_URL`, `SERVER_URL`, workspace custom domains. Localhost only allowed in `NODE_ENV=development`.
- `origin: undefined` (non-browser, curl, server-to-server) is passed through — intentional for webhook/server clients, browser won't expose response.
- **Assessment: CORS is correctly scoped. No wildcard issue.**

### 4f. XSS

- Zero occurrences of `dangerouslySetInnerHTML` in `twenty-front/src/` or `twenty-ui/src/`.
- **Assessment: No XSS surface found.**

### 4g. exe-os / exed Dependency

- `twenty-server` does not call out to `exed` or MCP at runtime. All exe-os integration is via stub modules (DNS, enterprise, usage stubs with `// Stub: exe-os manages X externally` comments).
- Database is accessed directly via `PG_DATABASE_URL` → TypeORM. Architecture is correct.
- **Assessment: No illegal service-to-service dependency on exe-os daemon.**
