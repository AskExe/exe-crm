# Finite company CRM read MCP (source-only)

`CRM_COMPANY_MCP_ENABLED=true` explicitly enables `/company-mcp` only alongside the complete existing `CRM_COMPANY_MODE=true` registration. The default is closed. This does not enable central key mint, company issuance, legacy `/mcp`, native admission or technical readiness. Ordinary native GET/off-mode routes retain their existing dispatch.

The transport follows the finite JSON-response subset of [MCP Streamable HTTP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). POST accepts one JSON-RPC request/notification (no batches), `Content-Type: application/json`, and an Accept header including both `application/json` and `text/event-stream`. Initialize negotiates only `2025-11-25`; subsequent requests require that exact `MCP-Protocol-Version`. GET and DELETE return 405 after current authorization; there is no SSE stream or MCP session identifier. `initialize`, `ping`, `tools/list`, `tools/call`, initialized and same-credential cancellation notifications are finite supported methods. Notifications return 202.

Each request requires exactly the owned `Bearer exk_…` format. Cookies, native keys and JWTs are rejected. Fixed Host and any present Origin must match the existing operator registration. Foreign Origin returns 403. Duplicate headers/JSON fields, selectors, framing ambiguity, encoded bodies and query-bearing routes are denied. The separate reviewed tenant edge currently strips `MCP-Protocol-Version`; it needs an independently reviewed finite header follow-up before this transport can be used through that edge.

Only four tools are exposed:

| Tool | Arguments | Native read |
| --- | --- | --- |
| `people_list` | `limit`: integer 1–100 | `/rest/people`, depth 0 |
| `person_get` | `id`: canonical lowercase UUID | `/rest/people/:id`, depth 0 |
| `customers_list` | `limit`: integer 1–100 | `/rest/companies`, depth 0 |
| `customer_get` | `id`: canonical lowercase UUID | `/rest/companies/:id`, depth 0 |

No tool accepts workspace, subject, company, audience, scope, upstream, query, relation, aggregate or identity selectors. Customers here means the existing native CRM companies object; there are no process/import/write/file/job tools.

The service validates fresh central authority and existing operator-to-native user/workspace binding, enters explicit native user ALS, and calls the shipped `RestApiCoreService.get` dispatcher with an exact server-created DTO. The native permission-aware object/field/row path remains authoritative. Nonempty native pre/post hooks remain closed by the existing company profile. After the native read completes, central authority and the current native permission fingerprint are checked again before serialization. Core owner never grants native administrator rights. Record permission denial/missing records return uniform 404. Invalid protocol/authority requests return 400, invalid or revoked credentials return 401, and authority/provider/database uncertainty returns 503. No denial clears cookies.

Limits are 8 KiB raw JSON body, depth 8, at most 16 header fields, 100 records, 256 recent hashed credential rate buckets, 30 requests per minute per credential, and eight active requests per process. Native JSON text is bounded to 256 KiB; the response includes both text and structured content, so their combined representation is approximately twice that bound. Response headers disable caching. A 15-second monotonic and absolute deadline plus disconnect/cancellation denies late positive serialization and propagates abort to central provider reads. Controlled MCP native FindOne/Many reads now use an internally owned master QueryRunner. Only the native read section runs in READ ONLY; before every sequential records/fixed-count query, PostgreSQL statement_timeout is refreshed to the smaller of three seconds and remaining monotonic/absolute request time. No nested relations, arbitrary filters/order/aggregates, cursor or offset are admitted. Ordinary native reads without the module-private control keep their existing dispatch. Abort prevents new SQL and positive results; active SQL stops by server timeout, not immediate AbortSignal cancellation. The code awaits terminal query, rollback and release before leaving the read control and before post-read central/provider authorization. A fixed generic own-process watchdog at request deadline plus five seconds (at most twenty seconds from request receipt) covers stalled native connect/BEGIN/read/rollback/release. Failed connect/BEGIN or uncertain rollback/release invokes the same fixed fatal policy; uncertain connections are never explicitly returned to the pool. This watchdog applies to the owned native lease, not all earlier native identity/cache lookups. The process exit is restricted to the isolated enabled company-mode CRM process and performs no host/foreign process actions. Production fatal policy is fixed; replacement is permitted only under NODE_ENV=test. Controlled tests exercise actual child-process watchdog exit and mocked native terminal timeout/cleanup ordering. They do not prove actual PostgreSQL/driver timeout behavior or accepted teardown capacity. Rate limits are process-local, not accepted capacity evidence.

Controlled tests exercise current permission drift/revocation, explicit ALS dispatch, malformed protocol/body/headers, key-only admission, uniform denial, rate/result bounds and no late positive response. They mock the native dispatcher and private authority boundary. Actual source-built Core/native two-company permissions, edge/client protocol integration and production capacity remain unproved and held. No source test activates acceptance.

## SDK interoperability SOURCE fixture

The explicit fixture `packages/twenty-server/test/company-mcp/sdk-interoperability.source-fixture.ts` runs the actual shipped ingress, Nest controller, service and protocol on owned loopback listeners. ONLY private authority and native dispatcher boundaries are controlled. It reads the existing official SDK1.29.0 cache without installing/copying/modifying it. It also launches the exact frozen edge e029 source as one owned Node child (bounded startup and TERM/KILL cleanup), with actual SDK→edge→native-route HTTP. No Docker, external endpoint, real identity/provider, native PostgreSQL, browser or acceptance operation is involved.

```sh
COMPANY_MCP_SDK_CACHE=/Users/exeai/.npm/_npx/8de95dd69bf75d62/node_modules/@modelcontextprotocol/sdk \
COMPANY_MCP_EDGE_SOURCE=/Users/exeai/.codex/worktrees/askexe-tenant-edge-company-mcp-contract \
NX_DAEMON=false node node_modules/jest/bin/jest.js \
  --config packages/twenty-server/jest.config.mjs --runInBand --no-cache \
  --testRegex 'sdk-interoperability.source-fixture.ts$' \
  --runTestsByPath packages/twenty-server/test/company-mcp/sdk-interoperability.source-fixture.ts
```

Twelve tests exercise initialize/initialized, tools/list, all four fixed reads, the SDK's optional GET/SSE405 fallback, real optional-reason cancellation and foreign-key cancellation isolation, no late positive result, current revocation and 400/401/503, uniform native404, foreign Origin/duplicate authorization/selectors/version denial, and exact edge protocol header forwarding. The fixture supplies a bounded Fetch-compatible Node HTTP wire because Node24's builtin fetch normalizes Host to its loopback URL; the adapter preserves the SDK-generated request and fixed Host/Origin on the actual wire instead of bypassing ingress. Only the exact owned loopback URL can be requested, with 3-second wire and body/result bounds; redirects/OAuth/network fallback are unavailable. This adapter is test-only and changes no shipped runtime source.

The fixture is deliberately excluded from ordinary `*.spec.ts` discovery because it requires exact existing external SDK/edge source suppliers, which CI must not silently download. It is an explicit reviewed source interoperability check, not proof of actual Core/native A/B ACL, PostgreSQL statement timeout, browser login, production transport or 100-user capacity. SSE/resumption, MCP session authority, optional progress/task metadata, arbitrary schemas/tools, OAuth fallback and writes remain outside the finite server contract. No runtime compatibility change beyond the independently frozen protocol fixes was needed.
